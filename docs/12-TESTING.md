# 12 — Testing & Quality Gates

> **Status:** Draft · **Version:** 1.20 · **Owner:** Engineering · **Last updated:** 2026-08-29
> **Authoritative for:** test strategy, the security leakage matrix, CI gates, release criteria.

## 1. Philosophy

Two rules shape everything below.

**Security tests are permanent.** Every leak class in `§4` has a test that runs on every commit,
forever. They are not a one-time audit; they are the executable form of the acceptance criteria in
`01-PRD.md §38`.

**Test the policy chain, not the endpoint.** A test that a download endpoint honors an ACL proves
little if preview, search, sync, MCP and the editor each re-implement the check. The chain is
implemented once (`03-LLD.md §12`), and the matrix in `§4` asserts that every surface routes through
it.

### 1.1 Test our integration, not somebody else's correctness

Whether ClamAV detects EICAR, whether an OCR model reads a page accurately, whether PDFium renders
a glyph correctly and whether Milvus ranks well are **their** problems, settled by their own test
suites. Ours is the wiring: that an `INFECTED` verdict quarantines the version and no read path
serves it, that a page yielding no text becomes a `FAILED` manifest rather than an empty `READY`,
that a candidate the index offers is dropped when the caller may not read it.

This matters for what gets built as well as what gets asserted. A test that measures a vendor's
accuracy fails when they improve their model, on a line nobody here can act on — and it tempts the
kind of infrastructure (emulating an amd64 antivirus daemon on an arm64 laptop) that buys a slower
copy of a check CI already runs.

The line is drawn at the boundary: **assert everything about what we hand them and what we do with
what they return.** Bounds we impose, refusals we make, states we record, and what reaches a caller.

### 1.2 A test is not believed until it has been watched to fail

Write the test, then **break the thing it tests on purpose** and confirm it fails *by name*. Restore,
and confirm it passes. A test that has never failed is a claim, not a check.

This is not a counsel of perfection — it has caught roughly eight of this project's own tests being
vacuous, and each one had been read and reviewed first:

- a concurrency test passed 3/3 against a naive implementation, because the pool was capped at two
  connections and the race could not occur;
- `S3`/`S4` stayed green with the denylist deleted, because a revocation also removes the ACL and the
  post-filter refused the file anyway — so the tests proved a different mechanism than they named;
- a `D24` test passed with the empty-document guard removed, because the chunker drops whitespace
  segments and a *different* guard caught it — the comment claimed the wrong one was load-bearing;
- an image-bomb test passed twice for two different wrong reasons: first a bad CRC made the file
  unreadable, then the decoder's own allocation limit refused it before our check was reached.

**The recurring shape: an assertion about an absence passes for free.** `excerpt == None`,
"no cross-tenant row", "no `set_status` in this module", "these bytes were never read" — all of them
hold trivially against an implementation that does nothing at all. Two habits close it:

1. **Include a positive control.** Assert that the thing *does* appear in the case where it should.
   Without a third document that receives its excerpt, every assertion in an excerpt test passes
   against code that returns `None` for everything.
2. **Say which mechanism the test proves.** When a deliberate violation does *not* fail a test, that
   is a finding: the test is proving something other than what its name says. Record which control
   actually holds the property rather than deleting the test or quietly rewording it.

A source-scanning test — one that asserts some string does *not* appear in a file — deserves special
care, because the needle it searches for appears in its own source. Two such tests here failed
against themselves on first run. Assemble the needle at run time, exactly as `CLAUDE.md` rule 11
prescribes for PEM banners.

## 2. Test pyramid

| Layer | Scope | Runtime | Where |
|---|---|---|---|
| Unit | Pure functions, policy evaluation, chunking, parsing | < 30 s | Every crate |
| Property | ACL resolution, cursor encoding, conflict handling, chunk boundaries | < 2 min | `proptest` |
| Integration | Real PostgreSQL + Redis + MinIO + NATS via testcontainers | < 10 min | `tests/` |
| Contract | OpenAPI schema conformance, event schema compatibility | < 2 min | CI |
| Security | The leakage matrix (`§4`) | < 10 min | `tests/security/` |
| E2E | Browser flows against a seeded stack | < 20 min | Playwright |
| Load | Search, upload, browse at target concurrency | Nightly | k6 |
| Chaos | Dependency failure injection | Weekly | Staging |

## 3. Fixtures

A deterministic seeded tenant set that every integration and security test shares:

```text
tenant-alpha
  users:      owner, member, viewer, guest, auditor, admin
  groups:     engineering, finance, external-partners (nested: finance > finance-leads)
  workspaces: engineering (MEMBERS_ONLY), board (RESTRICTED)
  libraries:  specs (sync on), contracts (sync off, CONFIDENTIAL default)
  files:      public.md, internal.docx, confidential.pdf, restricted.xlsx,
              pii-sample.csv, secret-key.txt, infected.eicar, huge.bin
  barriers:   segment-a, segment-b (incompatible)
tenant-beta
  mirror structure with identical file names and colliding fixture IDs
```

`tenant-beta` exists solely so every cross-tenant assertion has a realistic counterpart with the same
names — a test that passes only because the other tenant's file was called something else proves
nothing.

## 4. Security leakage matrix

Each row is at minimum one permanent test. A surface is not "shipped" until its column is filled.

### 4.2 Authorization

| # | Assertion |
|---|---|
| A1 | `preview=ALLOW, download=DENY` yields a rendition and **no** signed original URL. Both halves asserted in one test: the preview returns `200 image/png` carrying the pipeline's bytes, and the *store* reports zero `signed_download` calls — not generated and withheld, never asked for. | A2 | Export, print and copy are each independently deniable |
| A3 | A `DENY` entry overrides an inherited `ALLOW` at every level |
| A4 | Breaking inheritance materializes the effective set with no privilege gain. `enclave_authorization::break_file_inheritance` and `break_library_inheritance` collapse the whole chain — the resource's own entries included — by deny-wins and write the result onto the resource in the same transaction as the flag flip. Both flags carry the escalation, so both are covered: `a4_breaking_inheritance_materialises_and_gains_no_privilege` asserts the file case and sweeps five probes across principal, action and node for an unchanged verdict, `a4_breaking_library_inheritance_gains_no_privilege` asserts the library case, and `a_settings_update_cannot_break_inheritance` proves a settings replacement cannot flip the flag without the copy (`ENC-141`) |
| A5 | Direct object-key access without a signed URL fails at the storage layer. Asserted against the provider, not against our own refusal to build such a URL: the object is uploaded, confirmed readable *with* a signature, and then fetched anonymously by its real key — so a `403` cannot be a missing object in disguise. | A6 | A signed URL cannot be replayed after expiry, or after single use where supported. Expiry is asserted end to end against MinIO: a short-TTL URL is fetched successfully, then again after the TTL elapses, and the second fetch must be refused. **Single use is not covered and cannot be**: SigV4 pre-signed URLs have no server-side use counter, so no S3-compatible backend supports it. Rather than leave that implicit, the test pins the true behaviour — a second fetch *inside* the TTL succeeds — and requires the store to report `single_use_signed_urls` as `false`, so the short TTL (`plans/M1-CONTENT-CORE.md` D14) stays visibly the only control on a captured URL and no caller can rely on a property the backend lacks. `crates/storage/tests/minio.rs` (`ENC-153`) |
| A7 | Version-level reads respect the current file ACL, not the ACL at version creation |
| A8 | A watermarked artifact is never written to the rendition cache, and two viewers of one page share a base object keyed by neither of them. Structural rather than asserted at the write site: `RenditionKey` has three fields — version, profile, generator — and no constructor accepting a principal, so there is no key a watermarked artifact could be stored under. `crates/preview/tests/watermark.rs` (`ENC-147`) |
| A11 | A listing row's `capabilities` are identical to what the single-file endpoint returns for the same file and caller. Not cosmetic: `CLAUDE.md` requires the UI to render actions from this object and never re-derive permissions client-side, so if the two can disagree the product changes its mind about what a user may do purely because they clicked into a file. Both are built by one function from one action table and the same resolved decision, and the test asserts field-by-field equality across a page whose rows deliberately differ. `crates/api/tests/content.rs` (`ENC-152`) |
| A10 | A `REFERENCE`, `USER`, `GROUP` or `TAXONOMY` metadata value cannot resolve to another tenant's resource, and an unresolvable one is indistinguishable from a cross-tenant one. Otherwise a metadata field is an oracle for what exists elsewhere: set the value, see whether it is accepted. Shape is checked without a database and existence only inside a tenant-scoped transaction, so the two cases collapse by construction. `crates/metadata/tests/storage.rs` (`ENC-151`) |
| A9 | No field interpolated into a watermark can become markup. The layer is SVG carrying a display name and an email — fields the viewer sets on their own profile — so an unescaped `<script>` is stored XSS delivered on the preview path to every viewer of the document. Every interpolated field is attacked, and the payload must survive *escaped* rather than be dropped: silently discarding a hostile name would let an attacker blank their own watermark by choosing one. `crates/preview/tests/watermark.rs` (`ENC-147`) |
| A12 | A watermark obligation is discharged in the *bytes*, not delegated to the client. An overlay a client is asked to draw is one a client can decline to draw, and the obligation exists because the page must identify whoever is looking at it — so for raster renditions the mark is composited into the pixels before the response leaves. Two viewers of one page receive different bytes; a name the bundled face cannot draw is omitted rather than rendered as boxes, and if the *email* cannot be drawn the mark names nobody and the preview is refused. An artefact too small to carry a legible mark is refused rather than returned untouched — found by a test whose output came back byte-identical to its input. `crates/preview/tests/composite.rs`, `crates/api/tests/delivery.rs` (`ENC-169`) |

| A13 | **A deployment authorizes an administrative action, and authorizes it as the right one.** `ENC-619`: `main.rs` handed the engine `SelfServiceAuthorization`, so every route under `/api/v1/admin/**` was refused whoever the caller was — closed, and unusable. The pivotal test builds **two routers over one database**, one wired as `main.rs` was and one as it now is, and asserts the identical signed token is refused by the first and served by the second; without that leg the assertion would have passed against a handler that authorized itself, against a chain that allowed everything, and against a resolver returning allow. The refusals are paired in the same run with the administrator succeeding: a member, a workspace owner, an auditor, a service account **carrying the administrator's own subject id** (only `typ` differs), an administrator of the other tenant, and the administrator themselves once the row says `SUSPENDED` — the token is unchanged and still valid, which is the property that makes an incident response effective before it expires. The grant is a **set**, not a flag: `AdminGrants` holding only `write_config` does not answer `manage_policy`, because `06 §22` separates changing conditional access from changing branding. And an `Action::Admin` never reaches the inner ACL service — asserted against an inner double that allows *everything*, since `acl_entries.action` is free text and a workspace owner with `manage_permissions` must not be able to write themselves the tenant's policy right. `crates/api/tests/admin_authorization.rs`, `crates/authorization/{src/admin.rs,tests/admin_grants.rs}` |

| A14 | **A2, over HTTP, in both directions.** `ENC-719`–`ENC-721`: A2 had no test for four milestones because it had no surface — `crates/api` registered `download` and `preview` and nothing else, so "export, print and copy are each independently deniable" was a property of the ACL resolver that no caller could observe. Three routes now ask three different questions (`file.export`, `file.print`, `file.preview`), each named in one `const` that reaches both `PolicyEngine::enforce` and `HandlerAudit::refuse` so a refusal cannot be attributed to a different action from the decision it followed. Every refusal is paired with its positive control in the same test over the same database, because an assertion that a route refuses passes for free against a route that refuses everybody: a caller with `download` and **not** `export` is refused the export *and served the download*, and the converse caller is served the export *and refused the download*; the same pair for print; and a caller granted download, export and print but denied `preview` gets nothing from the thumbnail route, which is what stops the smallest and most-requested delivery response in the product from becoming the one that skips a permission. | A15 | **No original object-storage URL is generated on the export or thumbnail path** — not withheld, never asked for. Structural first: neither handler takes a `BlobStore`, they take a `PreviewPipeline` whose single method accepts a `ReadableVersion` and a profile and returns bytes, so "give me the original" is not expressible in the vocabulary they hold; `print_token` takes neither and serves no byte at all. Asserted from the store's side, which is the only side that can see the difference — a `CountingStore` records every `signed_download` and `read_range`, and the assertion is that the list is *empty* while both rendition paths return the pipeline's bytes, so the absence is not the free absence of a handler that did nothing. Both halves earned their keep: minting the URL and discarding it fails the store assertion and **not** the body assertion, and returning it fails the body assertion first. `crates/api/tests/delivery_routes.rs` (`ENC-719`, `ENC-721`) |
| A16 | **An obligation that cannot be discharged refuses the delivery, and the refusal reaches the audit trail.** Three decisions, and the asymmetries are the design rather than an oversight. `NO_DOWNLOAD` **refuses an export** — `06 §5.2` defines no-download as *the product will not deliver an original or downloadable representation*, and a flattened export is the second of those — and **does not refuse a print grant**, which carries neither bytes nor a URL; reading it as an implicit no-print would be rule 6's collapse arriving through the obligation set instead of through the action. `WATERMARK` is composited into the bytes of a `png` export and **refuses** a `pdf` one, because nothing in `crates/preview` marks a PDF (`ENC-723`), and the assertion is that the exported bytes **changed** — a response equal to the base rendition means the obligation was recorded and then dropped, which a status-only check cannot see. On a print grant it is recorded onto the capability and the mint refuses a principal the mark could not name. Each refusal leaves the `ENC-606` pair: the chain's `ALLOW` and the handler's `DENY`, sharing a `request_id`, the second carrying `handler:obligation` and the obligation's *kind* and never its payload. `crates/api/tests/delivery_routes.rs`, `crates/api/src/routes/delivery.rs` (`ENC-719`, `ENC-720`) |
| A17 | **A print token is spent by being redeemed, and PostgreSQL is what enforces that.** A grant that can be redeemed twice is a download with extra steps. Single use is one statement — `UPDATE print_tokens SET redeemed_at = now() WHERE … AND redeemed_at IS NULL … RETURNING` — whose predicate names the column it writes, so under `READ COMMITTED` the second of two concurrent redemptions blocks on the row lock, re-evaluates its `WHERE` against the updated row and matches nothing. A read-decide-write lets both observe `NULL` and both proceed, which is the defect `plans/M2-ACCESS-DELIVERY.md` D18 forbids for download budgets; a `DELETE … RETURNING` is correct on the race and destroys the evidence in the same statement. **Proved under concurrency, not sequentially**: two spawned tasks on two pooled connections with a `Barrier` holding both transactions open until they contend, asserting on the *pair* — exactly one `Some` and one `None`, so "both failed" fails as loudly as "both succeeded". The pool is opened with eight connections because an earlier concurrency test here passed 3/3 against a naive implementation with a pool of two (`§1.2`). A sequential test would have passed against the process-local `HashMap` this replaced, which is exactly why `ENC-724` needed a different test rather than a better one. The token is 256 bits from the OS CSPRNG, returned once, only its SHA-256 retained (D19). Watched to fail: deleting `AND redeemed_at IS NULL` reports "2 succeeded, 0 were refused". `crates/preview/tests/print_tokens.rs`, `crates/api/tests/delivery_routes.rs` (`ENC-720`, `ENC-724`) |

| A19 | **A container listing is trimmed by the same chain that would refuse each row, and the proof is a same-tenant caller.** `A18`'s lesson applied where it was about to be repeated. `WorkspaceRepository::list_by_tenant` returns every workspace in the tenant *by design* — the repository takes no authorization decision — so the whole security of `GET /workspaces` and `GET /workspaces/{id}/libraries` is the batch trim after it, and a cross-tenant fixture cannot see the trim at all. | A20 | **Creating a folder is decided against the container it would go into, and the proof is a same-tenant caller with no grant on *that* container.** `ENC-788`: `POST /libraries/{id}/folders` is the first write on the file tree anything serves, and the resource it enforces `container.create` on is the **named parent** when `parentId` is given and the library otherwise — never the library id in the path, which is the obvious and wrong reading. | A20 | **A print grant has exactly one place to be spent, and every way of failing there is the same `404`.** `POST /files/{id}/print` is the redemption `ENC-720` shipped without. Seven causes — never issued, expired, already redeemed, minted for another file, another actor, another sign-in, or in another tenant — all make the redeeming statement return zero rows, so no arm exists that could tell them apart and rule 7 holds by construction rather than by seven `if`s that must keep agreeing. Every refusal is paired with a positive control in the same run: a real mint, a real first redemption returning `200 image/png`, and a *second* freshly minted grant that also succeeds — without which the whole row passes against a route that refuses everybody. | A21 | **A print grant is bound to one principal, and row-level security cannot hold that — so the test uses a same-tenant thief.** Two callers in `tenant-alpha`, both holding `file.print` on the same file: the chain allows both and RLS matches the row for both, so the only thing that can refuse the one who did not earn the grant is `actor_id`/`session_id` in the redeeming statement's `WHERE`. | # | Assertion |
|---|---|
| S1 | Keyword search returns nothing from an inaccessible library |
| S2 | Semantic search returns nothing from an inaccessible library |
| S3 | **After a permission revocation, the revoked file disappears from search results immediately**, before any index update completes. The candidate generator is unchanged across the revocation — it still proposes the file, as a real index would until a worker catches up — and the post-filter drops it. `crates/search/tests/postfilter.rs` (`ENC-506`) |
| S4 | With the invalidation worker deliberately stopped, S3 still holds. There is no worker in the test at all, which is the assertion. The two `None`s are asserted equal, and the distinction between them is required to appear exactly once, in the operator-facing `excerpt_withheld` counter. `crates/search/tests/lexical_content.rs` (`ENC-529`). Asserted a second time on the **dense** path against live Milvus, because `ENC-538` made that path produce excerpts that are *new objects* — cut from the chunk by `excerpt::preview` rather than passed through — so the assertion is run against candidates a real index produced rather than inferred from the lexical case. ### 4.12 Quotas and capacity

`plans/M4-GOVERNANCE.md` D31. The same shape as `H3` — the limit in the `WHERE` clause of the
statement that spends the resource, a zero-row result as the refusal — applied to stored bytes
instead of share-link downloads.

`Q1`–`Q6` are the statement (`crates/db/tests/storage_quota.rs`, `ENC-584`). `Q7`–`Q11` are the
*wiring* (`ENC-589`), and they exist because the two are separable in exactly the way §2 of the
plan is about: `ENC-584` shipped a correct charge that nothing called, and a control that is
switched off is indistinguishable from an absent one except in the compliance answer. So the
question `Q7`–`Q11` ask is not "does the statement refuse" but "does the real write path reach it,
in the real transaction, before the row it pays for" (`§1.1`).

### 4.13 Surfaces a caller reaches before authenticating

Two endpoints answer a request that carries no credential: `GET /api/v1/bootstrap` and
`GET /health/dependencies` (`docs/05-API.md §19`). Both have a second, larger answer for a caller
who has authenticated, and in both cases the split is a **pair of types** rather than a filter —
the public response has no field the private data could occupy, so there is nothing to forget to
clear. That makes every assertion below an assertion about an absence, which `§1.2` says passes for
free; every row therefore names the positive control that runs in the same test, over the same app,
and makes the silence mean *withheld* rather than *never produced*.

| # | Assertion |
|---|---|
| N1 | **The anonymous bootstrap response carries no session, no tenant id, no user id and no locale resolved from a tenant or a user record.** The control is the authenticated request in the same run, which receives all four with real values — including `locale.source: "user"` from a `users.locale` the test writes first, so the anonymous caller's `source` is a step of `docs/14 §3` it demonstrably *could* have reached and did not. The identifiers are searched for as strings as well as by key, because a leak need not arrive under the name the schema gives it, and each search is paired with the same search against the authenticated body. Broken by having the anonymous branch construct a `Session`: fails naming the forged payload. `crates/api/tests/bootstrap.rs` (`ENC-725`) |
| N2 | **The anonymous bootstrap response is byte-identical for alpha's host, beta's host and a host that routes no tenant.** Not a consequence — `enclave_db::resolve_routed_tenant` exists and `POST /auth/login` uses it — but a decision: a response that varied by `Host` is a tenant-enumeration oracle for a caller holding nothing (`CLAUDE.md` rule 3). Three identical bodies also hold trivially for an endpoint that answers the same thing to everything, so the control is a fourth request varying `Accept-Language`, which must differ. Compared as bytes, not as parsed JSON, because `serde_json::Value` sorts keys and would call two responses equal that a client would see as different. `crates/api/tests/bootstrap.rs` (`ENC-725`) |
| N3 | **The unauthenticated dependency summary is one word, and neither half discloses where anything lives.** The summary's key set is asserted *equal* to `["status"]` rather than merely lacking `dependencies` — a count, or a list of names with their statuses elided, leaks the deployment's shape just as surely and would pass the narrower assertion. The topology scan looks for the host, port and database name **taken from the DSN this deployment was handed**, and asserts they appear in that DSN first: a search for strings the deployment never had proves nothing. Broken by adding an `endpoint` field to `Dependency`: fails naming the host. `crates/api/tests/dependencies.rs` (`ENC-726`) |
| N4 | **No dependency is ever omitted, and an unprobed one is neither `up` nor `down`.** An absent dependency reads as a healthy one, so the six components this process holds no client for are listed with `evidence: "none"` and `status: "unknown"`, and the reported name set is compared for *equality* — a component dropped from the report fails here rather than shrinking the expectation with it. The other direction is asserted too: six `unknown`s must leave the verdict `healthy`, because a report that is permanently degraded is a report nobody reads. `crates/api/tests/dependencies.rs` (`ENC-726`, `ENC-729`) |
| N5 | **The authenticated half of each endpoint is decided by the chain, and a refused caller gets a refusal — not the public payload with a different status.** `xtask policy-routing` proves `enforce` is *reachable* from a handler; it cannot prove `enforce` **dominates** the authenticated branch, which needs MIR. So each test swaps exactly one stage for one that refuses and asserts the `docs/05-API.md §5` envelope, the absence of any bootstrap or dependency payload, and one non-`ALLOW` audit row (`CLAUDE.md` rule 10). The control is the identical request against the allowing composition, differing in that one stage and nothing else. Broken by degrading a refusal to the anonymous answer — the plausible-looking regression, since bootstrap "should always answer something" — which fails with `200` against `403`. `crates/api/tests/bootstrap.rs`, `crates/api/tests/dependencies.rs` (`ENC-725`, `ENC-726`) |
| N6 | **Each tenant's bootstrap session reports its own `tenants` row.** The one query in either handler that row-level security does **not** cover: `tenants` carries no `tenant_id` column, so `migrations/0002` gives it no policy, and `WHERE id = $1` is the only layer. Stated as a positive pair rather than as a cross-tenant absence for exactly the reason `T8` records — "alpha does not see beta's row" is satisfied by a single-row database — so alpha and beta each read their own in one run, and a predicate-free `SELECT` answers both with the same row and fails at least one leg. Verified by deleting the predicate: beta was served alpha's row. `crates/api/tests/bootstrap.rs` (`ENC-725`) |

### 4.14 What the client may state about a decision

The rows above are about what the server must not disclose. These are about what the **client** must
not assert — and they are security rows rather than product ones, because each failure teaches a
user to misread a real policy decision.

The product has exactly one visual language for *the policy refused you*: a dimmed control with a
reason beside it (`docs/09 §12`, `docs/06 §24`). That language is how a user learns what DLP, a
barrier or a conditional-access rule did. Every time something else wears it — a feature that is
merely unwritten, or a sentence the client made up — the language means slightly less, and it is
eroded on the harmless surfaces first and spent on the one that matters.

| # | Assertion |
|---|---|
| C1 | **A not-yet-built control is never rendered in the denial treatment, and is never focusable.** (`ENC-673`, D33; the component contract is `docs/17 §10` F2.) The two are values of one `data-state` attribute rather than strings assembled at runtime, so "share no selector" is checkable rather than aspirational: the tests read the shipped stylesheets, collect every selector mentioning `denied` and every one mentioning `unbuilt`, and assert a denied control matches the first set and none of the second, and vice versa. Comparing `className` would prove nothing — both are states of `.ui-btn` and the strings are identical. Focus is the other half and it runs the opposite way for each: a denial **stays in the tab order**, because a keyboard user must be able to reach it to hear why, and an unbuilt control leaves it, because there is nothing to find out. Every absence is paired in the same run with a probe that does have what is being looked for, so a screen that failed to mount cannot pass. `web/tests/unit/ask-unbuilt.test.tsx` (Ask is the largest population of dimmed controls in the product, so it is where the habit would be learned), `web/tests/unit/library-capabilities.test.tsx` (the view bar, where the two sit side by side), `web/tests/unit/design-system.test.tsx` |
| C2 | **A denied capability's explanation comes from the server, and the client composes none.** (`ENC-674`.) `capabilities` reports `false` and `capabilityReasons` names the `docs/05 §5` code that made it `false`; the client maps code → catalog sentence and does nothing else. The lookup is keyed on the code and on no file state, role or classification, which is what separates *rendering* a decision from re-deriving one. Three legs: the codes map one-to-one onto eighteen distinct sentences, so the client never flattens a distinction the server drew; an unrecognised code falls back to a restatement of the refusal rather than to a guess at its cause; and **no denial sentence interpolates**, so a rule name, threshold or matched value has no route to a user (`CLAUDE.md` rule 10, `docs/06 §24`). The last is asserted structurally rather than by banned vocabulary — a word-list failed on "a retention policy prevents this item from being deleted", which names a kind of control and not a policy, and a test that bans the word teaches people to reword around it. The reason is text associated by `aria-describedby`, never `title` alone (`docs/09 §15`). `web/tests/unit/capability-reasons.test.tsx`; the server half is `read_only_and_no_download_only_ever_subtract` in `crates/api/src/content.rs` |
| C3 | **A search says which retrieval actually ran, and never describes a mode it is not in.** (`ENC-675`, `docs/09 §10`.) `diagnostics` carries `mode` and `degraded` as two independent facts and the notice has one variant per combination: lexical-only is a product state, dense-only is a *different* product state, and a fallback is an incident. They are not interchangeable — lexical loses meaning, dense loses the exact string — and the two product states carry the `Later` chip while the incident must not, because marking a transient outage as a roadmap item is the C1 confusion arriving through copy. The row exists because the failure has already happened in both directions: the route reported `degraded: true` unconditionally until `ENC-698`, and the client then read every non-hybrid mode as lexical, so a healthy semantic search was described as having no semantic search. Each variant's assertion names the sentence that must appear **and** the one that must not. `web/tests/unit/search-retrieval-notice.test.tsx`, `web/tests/a11y/routes.spec.ts` |

## 5. Structural CI gates

Assertions about the codebase itself, not its behavior:

| Gate | Rule |
|---|---|
| RLS coverage | Every table with a `tenant_id` column has RLS enabled **and** forced, with a policy |
| Grant coverage | `enclave_app` can reach every tenant-scoped table, still cannot `UPDATE`/`DELETE` `audit_events` or its partitions, and holds neither `SUPERUSER` nor `BYPASSRLS`. The RLS gate cannot see any of this: it checks the policy, not whether the role it applies to can use the table — the gap that let a cross-tenant read return `200` in PR #22 |
| Composite FKs | Every FK between tenant-scoped tables includes `tenant_id` |
| Policy routing | Every Axum route handler reaches `PolicyEngine::enforce` (verified by a call-graph lint) |
| Audit coverage | Every site that constructs a refusal does so where `PolicyEngine::enforce` records it, and the row it writes names the stage that refused. Two halves in one job, because they fail differently: deleting `record_deny` from the chain leaves the lint green, and dropping the stage attribution leaves both the lint and `enclave-core`'s own tests green |
| No raw pool | No `sqlx::query*` outside the `db` crate bypasses `TenantScoped` |
| Obligations | `PolicyDecision` is `#[must_use]`; no `let _ =` discards it |
| Secrets | No literal credential patterns in configuration files or fixtures |
| Migrations | Numbered, checksummed, no gaps; contract-phase migrations flagged for review |
| Dependencies | `cargo audit` and `cargo deny` clean; SBOM generated |
| API contract | Generated OpenAPI matches the committed snapshot, or the diff is explicitly approved |
| Accessibility | axe passes on every primary route |
| Bundle size | Main bundle ≤ 250 KB gzipped |
| i18n | No untranslated user-facing string literals in `web/src` (`14-I18N-L10N.md §8`) |

## 6. Performance tests

Nightly k6 against staging, asserting the budgets in `03-LLD.md §23` and `09-UX-WHITE-LABELING.md §2`:

- browse a 100 000-item folder — first page P95 < 400 ms;
- search at 50 RPS — P95 < 500 ms, post-filter drop ratio < 5%;
- 100 concurrent 1 GB uploads — no API memory growth beyond the configured buffer;
- 500 concurrent preview requests — rendition queue drains within SLO;
- policy decision under cold cache — P95 < 300 ms.

A regression greater than 20% against the previous week fails the build.

## 7. Chaos tests

Weekly in staging, each asserting the row in `02-HLD.md §24`:

kill PostgreSQL primary (failover, no data loss) · kill Redis (degrade, no authoritative loss) ·
kill Milvus (search degrades, files work) · kill NATS (outbox retains) · block the embedding provider
(indexing pends) · block AV (uploads hold) · block SMTP (retries then DLQ) · block Vault (leases
continue, new fetches fail closed) · partition object storage (metadata browsing continues).

## 8. Manual and external testing

- **Screen-reader pass** (NVDA + VoiceOver) on primary flows each release.
- **Localization pass** in one RTL and one long-string locale each release (`14-I18N-L10N.md §9`).
- **Penetration test** at least annually and before any major release, scoped explicitly to the
  matrix in `§4` plus standard web application testing.
- **Restore drill** monthly (`11-OPERATIONS.md §4`).
- **Upgrade drill** from the previous two minor versions before each release.

## 9. Release criteria

A release ships only when all of the following hold:

1. every test in `§4` passes — no skips, no quarantined security tests;
2. structural gates in `§5` pass;
3. no open SEV1/SEV2 defects;
4. performance within 20% of the previous release;
5. migrations verified forward **and** with the previous release running against the new schema;
6. accessibility and localization passes complete;
7. the changelog, upgrade notes and any new runbook sections are written;
8. the error budget is not exhausted (`11-OPERATIONS.md §1`).

## 10. Coverage expectations

Line coverage is a weak signal and is not a gate. What is gated:

- 100% of the matrix in `§4`;
- 100% of policy-engine branches (every effect, every obligation, every fail-closed path);
- every state transition in the upload, incident, index-manifest and sync state machines;
- every error variant in `03-LLD.md §22` reachable from at least one test.
